# System Design Lab

**Learn system design by building tiny versions of real systems — in Kotlin, with tests, one problem at a time.**

Not slides. Not memorised diagrams. Each problem takes one real situation — *how does Uber find the nearest driver? why does Rapido ask for an OTP? how does Kafka avoid losing messages?* — shrinks it down to a few arrays and maps, and asks you to make it work. The tests tell you when it does.

> **Rule #1: write the solutions yourself.** No AI for the solution code. Use AI (or anything else) to *explain concepts* or *review* your finished work — see [RATING.md](RATING.md).

## The levels

| Level | Name | What it feels like |
|------:|------|--------------------|
| 0 | **Foundations** | The basics every backend person needs: REST APIs, indexes, transactions, load balancers, queues, replicas, auth tokens, URL shortener |
| 1 | **Warm-up** | One data structure, a few rules. 30–60 min |
| 2 | **Building blocks** | A classic technique: sliding windows, TTLs, idempotency, LRU, partitions. 1–2 h |
| 3 | **Realistic** | A real subsystem: spatial index, consistent hashing, tries, webhooks with backoff. 2–3 h |
| 4 | **Hard** | Several moving parts and trade-offs: rate limiting, fan-out, caching strategies, rebalancing. 3–4 h |
| 5 | **Boss** | Distributed-systems ideas in miniature: replication, sagas, 2PC, event sourcing, sync conflicts. An evening or two |

Levels run **across** apps: Level 1 has one easy problem from every app, Level 2 one medium problem from every app, and so on.

## How to go through it — in rounds

1. **Round 0:** all of Level 0 (in order — later problems build on earlier ideas).
2. **Round 1:** all of Level 1. Then Level 2, 3, 4, 5.
3. **New apps get added over time** (see [ROADMAP.md](ROADMAP.md)). New problems are always **appended** to the end of each level, so nothing you've solved moves. When a new batch lands, do its Level 0/1 problems as a warm-up, then continue at your current level.

You don't have to finish every problem in a level before moving up — but try to finish at least **two thirds**.

## One problem, step by step

```
levels/level-2-building-blocks/09-netflix-lru-edge-cache/
├── PROBLEM.md      ← 1. read: the situation, rules, example + "Your plan, step by step"
├── CONCEPTS.md     ← 2. read: the ideas you need, explained (no solution)
├── HINTS.md        ← 3. only when stuck: three hints, each hidden until clicked
├── src/main/kotlin ← 4. every function is declared with a comment — fill in the TODO()s, step by step
├── src/test/kotlin ← 5. run these; don't edit them
├── NOTES.md        ← 6. write your design notes (why, complexity, what breaks at scale)
└── REVIEW.md       ← 7. score yourself, then get a review (see RATING.md)
```

Full guide: **[HOW-TO-SOLVE.md](HOW-TO-SOLVE.md)**.

## Setup

You need **JDK 17+** (Android Studio's bundled JDK works). Open the folder in **IntelliJ IDEA** or **Android Studio** — it's a normal Gradle project; every problem is its own module.

```bash
# run one problem's tests
./gradlew :l1-uber-nearest-driver:test

# check that everything still compiles (tests of unsolved problems will fail — that's expected)
./gradlew compileTestKotlin

# see your progress
python3 tools/scoreboard.py
```

The module name of each problem is in its `PROBLEM.md` and in [CATALOG.md](CATALOG.md). In the IDE you can also just click the green ▶ next to a test class.
